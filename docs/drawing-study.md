### 3 กลุ่มรูปแบบที่พบ
1. **ตู้เดียวติดหม้อแปลง (PP0817B, PP0985B, PP1047A)** — วงจรทั้งหน้าเป็นตู้เดียว, Terminal แบบ `-TB01`/`-TBL-X2`, Outline มีประตูนอก + แผงใน (swing panel) + mounting plate + ผนังข้าง
2. **LCC + RCC แยกหน้า (PP0915A)** — หัวกระดาษเป็นข้อความจริง (สารบัญอ่านได้), Terminal `X1–X8` ซ้ำกันในทั้งสองตู้ (`LCC-TB-X3` / `RCC-TB-X3`)
3. **LCC + RCC ในหน้าเดียวกัน (PP0922B, PP0993B)** — แต่ละหน้าแบ่งกรอบประ `+LCC` / `+RCC` / `+TR` / `+MDC` / `+SCPS`
   ขั้วชื่อเดียวกัน (`-X3.201`) อยู่ทั้งสองตู้และต่อกันด้วยสายภายนอก (เส้นประ) · RCC เป็นตู้ตั้งพื้น indoor:
   อุปกรณ์อยู่บนประตูหน้า (กระจก) + แผงด้านในที่มีรางวายเวย์แนวนอนทุกแถว + ผนังข้าง A-A / B-B ที่ติด Terminal X1–X8

## 3. สิ่งที่ปรับในโปรแกรมจากการศึกษา

| ปัญหาที่พบ | การแก้ |
|---|---|
| มีหลายตู้ในโปรเจกต์เดียว (LCC + RCC) | มุมมอง/อุปกรณ์มี `LOC.` ของตัวเอง, node ที่ลากข้ามตู้ถูกแยกวางแผนเป็นสายภายในของแต่ละตู้ (ส่วนข้ามตู้ = สายภายนอก), Excel ออกชีท `IN LCC` / `IN RCC` แยกกัน |
| ขั้วชื่อซ้ำทุกตู้ (X1–X8) | ใช้ชื่ออุปกรณ์แบบ IEC `+RCC-X3` (ในตาราง Excel แสดง LOC = RCC., CMP = -X3) |
| เขียนขั้วแบบ `-X3.201` | ช่อง Netlist รับทั้ง `-X3:201` และ `-X3.201` |
| Outline ของแต่ละตู้อยู่คนละหน้า | หลายภาพพื้นหลัง (“+ หน้า Outline”) เลือกสลับได้ |
| โครงตู้ต่างกัน (ตู้ติดหม้อแปลง vs ตู้ตั้งพื้น) | เครื่องมือในแท็บผังอุปกรณ์: วาดมุมมอง (mounting plate / ประตู / ผนัง) + ใส่ขนาดจริง, วาดรางวายเวย์ (จับแนว/ต่อจุดตัดอัตโนมัติ), จุดเชื่อม/บานพับระหว่างมุมมองใดก็ได้ (รวมผนังข้าง ↔ แผงหลัก), วาง/ลบอุปกรณ์ |
| ชื่ออุปกรณ์ใน Outline ไม่ครบ | ดึงตำแหน่งจากป้ายที่เป็นข้อความ + สร้างอุปกรณ์ใหม่จากป้าย, อุปกรณ์จาก Netlist ที่ยังไม่วางแสดงเป็น “ยังไม่วาง” |
| สายจัมเปอร์ระหว่างขาบนอุปกรณ์ตัวเดียวกัน (เช่น KS1:12→KS1:10) ถูกคิดว่าออกไปรางวายเวย์ | คิดเป็นจัมเปอร์ 50 mm (ตั้งค่าได้) — PP1047A รวมลดจาก 804 m เป็น 799 m |
| โปรเจกต์ใหม่ | ปุ่ม 🆕 โปรเจกต์ใหม่ (ระบุตู้ได้หลายตู้) |

## 4. ทดสอบใช้งานจริงกับ PP0993B (LCC + RCC) ผ่านหน้าจอ

ทำผ่าน UI ทั้งหมด (สคริปต์ Playwright): สร้างโปรเจกต์ใหม่ → เปิด PDF → เพิ่ม Outline หน้า 3 เป็นตู้ RCC (ได้ป้าย X1–X8, CTTR-X1 อัตโนมัติ)
→ วาดมุมมอง 4 ส่วน (ประตูหน้า, แผงด้านใน, ผนัง A-A, ผนัง B-B) → วาดรางวายเวย์ 18 เส้น → จุดเชื่อม 3 จุด (บานพับประตู, ผนัง A, ผนัง B)
→ นำเข้า netlist ตัวอย่างจาก Sheet 17 (8 node รวม F2 ที่อยู่ทั้ง LCC และ RCC) → วางอุปกรณ์ → ส่งออก Excel

ผล: ได้ชีท `IN LCC` และ `IN RCC` แยกกันถูกต้อง, F2 ถูกแยกเป็น LCC `-X3.203 → -43FLR.3` และ RCC `-X3.203 → -43RS.4 → -43RS.2`,
สายจากประตูผ่าน `HINGE`, สายจาก Terminal ผนังข้างผ่าน `SIDE-A`, ส่วน LCC ที่ยังไม่วางผังแสดง “ยังไม่มีเส้นทาง”
(netlist ในการทดสอบนี้เป็นตัวอย่างบางส่วนเพื่อทดสอบเครื่องมือ ไม่ใช่ wiring list ที่ตรวจแล้ว)

## 5. ข้อจำกัด / งานที่ยังเหลือ

* Netlist ยังต้องได้มาจากการไล่แบบ (ภาพ) — ถ้ามีไฟล์ CAD ต้นฉบับ (DWG/DXF) หรือ PDF ที่ export แบบเก็บข้อความ จะทำตัวอ่านอัตโนมัติได้
* ตำแหน่งขั้วตามลำดับบน Terminal strip มีเฉพาะ PP1047A (`terminals` ในไฟล์ข้อมูล) — โปรเจกต์ใหม่ใช้จุดกึ่งกลางของ TB
* Short link bar ของโปรเจกต์ใหม่ยังต้องใส่ในไฟล์โปรเจกต์ (JSON) — ยังไม่มีหน้าจอแก้
* มาตราส่วนของแต่ละมุมมองตั้งจากความกว้างจริงที่กรอก ความยาวสายจึงเป็นค่าประมาณ

สิ่งที่แก้ (ใช้ได้ทั่วไป ไม่ผูกกับแบบนี้)
* กรอบตู้แบบเส้น dash-dot (`+TR`) และกรอบแนวตั้ง — อุปกรณ์ในหม้อแปลงไม่ถูกนับเป็นสายภายใน
* ตัวอักษรที่สัมผัสเส้นสาย = ส่วนของสัญลักษณ์ (ส่วนโค้งคอนแทค → C/0, หัวลูกศร → V) ไม่ใช่ขา/เบอร์สาย
* จุดต่อที่วาดเป็นวงกลมซ้อน, เส้นสั้นระหว่างวงกลม Terminal กับสาย, สายเส้นประเข้าขั้ว
* Terminal เชื่อมสายทั้งสองด้านของวงกลมเดียวกัน
* ชื่ออุปกรณ์: ป้ายในกล่อง (-47L), แถวช่องต่อกัน (annunciator -AN, ป้ายช่อง AN19), คอลัมน์ขา (-8AM), ป้ายเหนือคอนแทคแนวนอน (-49F 98/97),
  สวิตช์เลือกที่ป้ายอยู่ใต้ปลายเส้นกลไก (-43CA, 83C ที่ไม่มีขีด), ป้าย -TB ไม่รับขาอุปกรณ์, ตำแหน่งสวิตช์ (-OFF/-ON/-AUTO) ไม่ใช่อุปกรณ์
* ตัวเลขมีจุดในแนวตั้ง (1.12), cross reference แนวตั้ง, ชื่ออุปกรณ์ที่เป็นข้อความจริงของ PDF

ที่ลองแล้วไม่ใช้: เชื่อมรอยต่อรูปตัว T ที่ไม่มีจุด (ความถูกต้องการเชื่อมตกจาก 99% เป็น 80%),
จับคู่ cross reference ที่ชี้หากัน (เชื่อมผิดมากกว่าที่ได้)

ยังพลาด (10% ที่เหลือ): ตัวอักษรอ่านผิด (`COM1`→`CON1`, `GND`→`GN0`, `+125` แยกเป็นสองคำ), รอยต่อ T ไม่มีจุด (ขา A2 ของ 88F),
ขาที่ป้ายอยู่ไกลจากสัญลักษณ์ — ตัวเลขนี้มาจากแบบเดียว (PP1047A); แบบ Type อื่นต้องมี netlist/Excel อ้างอิงจึงจะวัดได้

## 8. วัดกับ Excel wiring list งานจริง (PP0993B LCC/RCC, PP0817B)

แปลง Excel เป็น netlist อ้างอิงด้วย `python3 tools/xls_reference.py <ไฟล์.xls> "IN LCC" LCC. ref.json`
แล้ววัด `node tools/eval_reading.js ผลการอ่าน.json ref.json --cabinet LCC.` (Excel ไม่ถูกเสมอไป — ใช้เป็นแนวทาง)

| แบบ | หาขาได้ | ขาที่หาได้ถูก | การเชื่อม ถูก / ครบ |
|---|---|---|---|
| PP1047A TCC (netlist ไล่มือ) | **90%** | **97%** | 99% / 96% |
| PP0817B LCC | 60% → 67% | 63% → 80% | 71% / 94% → 82% / 95% |
| PP0993B LCC | 28% → 66% | 37% → 72% | 25% / 14% → 84% / 52% |
| PP0993B RCC (sheet `IN RCC`) | 31% → 47% | 68% → 76% | 58% / 28% → 78% / 38% |

แก้ในรอบนี้ (ทั่วไป): กรอบตำแหน่งที่เป็นคำบรรยาย (`TRANSFORMER TANK SIDE`) และรหัสตู้ที่เป็นข้อความจริง (`LCC.`),
ขาที่อยู่นอกทุกกรอบบนหน้าที่มีกรอบตู้ไม่นับเป็นตู้แรก, ไม่อ่านชื่ออุปกรณ์ในตารางชื่อแบบ, สัญลักษณ์กลมขนาดใหญ่ (มอเตอร์)
และสามเหลี่ยม (LED/ไดโอด) เป็นตัวอุปกรณ์, ขาคู่ 1-2 / 13-14 / 95-96 ในแนวเดียวกัน, ชื่อขึ้นต้น -O / -0 = -Q,
ค่าพิกัด (-1.5A) ไม่ใช่อุปกรณ์, ป้าย Terminal แบบ `-X6.M11`, ทางแยกบัสแบบเส้นหักเฉียง (jog), ชื่อสายไม่มีตัวเลข
(`DC`) ไม่รวมข้ามหน้าเว้นแต่มี cross reference คู่กัน
